# AI 模块《它变了》整合说明

> 这一份是给**负责合并的同学**看的。看完你应该能在 5 分钟内把它接进产品。

---

## 一、它是什么

人工智能方向（`/tracks/ai`）的完整工作台。

**一句话**：养一只数字识别模型。从一个连 1 和 7 都分不清的灰球开始，经过五章，
把它养成能认手写体的模型 —— 而它最后长成什么样，取决于你一路上做的选择。

**五章 + 一个结算**：

| 章 | 标题 | 教的概念 | 核心玩法 |
|---|---|---|---|
| — | **领养** | — | 给它取名字（最多 5 个字），可跳过建议名 |
| 00 | 开局一只啥也不会的 | 样本 | 拖数字喂它，按喂食比例三阶段长大 |
| 01 | 它偏食了 | 数据不平衡 | A 补样本 vs B 调参（对照实验） |
| 02 | 它只会做原题 | 过拟合 | **自己手写一个数字，被它当面拒认**；喂变形样本 |
| 03 | 它被人教坏了 | 数据质量 | **抓内鬼**：找出图与标签对不上的样本 |
| 04 | 出道 | 泛化 | 从数据清单里挑样本喂它（清单里混着标错的） |
| — | 模型身份证 | 行为画像 | 按你的行为给出性格标签 |

**每一章内部的六个环节**（由 `ChapterRunner` 统一提供）：

```
① adopt  领养取名（只有第 0 章、且还没取过名字时出现）
     ↓
② intro  开场台词
     ↓  点"开始 →"
③ game   核心玩法（每章不同）
     ↓  达标后出现"带它去打 →"
④ boss   BOSS 对战（10 题）
     ↓  点"继续 →"
⑤ clear  变形演出（滚动换形态 + 徽章 + 学会的词）
     ↓  "进入下一章 →" 或 "看看后面的安排"
⑥ done   后面的安排（有返回与继续两个出口，不是死路）
```

## 四、一条必须遵守的架构约定

**每章的"判定规则"必须只有一个实现，而且放在 `games/xxxRules.ts` 里。**

成绩单和 BOSS 战**调同一个函数**，共享同一份进程级记录：

```
        ┌────────────────────────────┐
        │  xxxRules.ts               │
        │   · accuracyFor()          │  ← 唯一的正确率函数
        │   · 进程级共享记录（bag）   │  ← 唯一的"喂了什么"
        └──────────┬─────────────────┘
            ┌──────┴──────┐
       ┌────▼────┐   ┌────▼────┐
       │  成绩单  │   │  BOSS   │
       └─────────┘   └─────────┘
```

**为什么必须这样 —— 这是踩了三次坑换来的：**

| 曾经的做法 | 出现的鬼事 |
|---|---|
| 成绩单和 BOSS 各写一套公式 | 界面显示"只考 6/8：25%"，但"带它去打"按钮已经亮了 |
| 喂食记录存两份（玩法组件一份、章节容器一份） | 刚补完就打 BOSS，BOSS 拿到旧数据 → **成绩单全对却打不过** |
| `classify()` 的剧本锚点无条件生效 | 第 3 章清完内鬼也永远赢不了（见下） |

**加新章节时请照这个模式做**，否则同样的 bug 会再来一次。

## 五、三个容易被误伤的地方

### 1. `modelBrain.ts` 的剧本锚点

第 3 章有一幕必须每次发生：**"3 被认成 8"**（那是整章的触发器）。
所以 `classify()` 里有个 `scripted` 标记强制它答错。

但它**只在调用方没有指定准确率时才生效**：

```ts
const scripted = state === 'poisoned' && truth === 3 && accOverride == null
```

**别把 `&& accOverride == null` 去掉。** 去掉之后，玩家把内鬼清干净、外面传进来
0.97 的正确率，它还是把每个 3 都判错 —— BOSS 永远打不过，而且日志完全对不上账。

### 2. `ChapterPlay` 的兜底分支

**兜底必须明确报错，不能默认渲染某一章。**

以前兜底是 `<Chapter0 />`，于是第 2 章点"进入下一章"时因为第 3 章还没做，
就落进兜底又演了一遍第 0 章 —— 用户看到的是"第 0 章和第 1 章无限循环"。

另外注意：`'card'`（模型身份证）**不在 `CHAPTERS` 里**，必须在
`getChapter(current)` 之前拦下来，否则会掉进"这一章还没有工作台"。

### 3. 地面阴影有严格的位置约束

**阴影必须满足两条，否则看起来就是"贴纸在动"而不是"生物在地上"：**

| 约束 | 为什么 | 怎么做 |
|---|---|---|
| **不能旋转** | 地是平的。身体左右歪的时候影子跟着歪，一眼假 | 动画类挂在 `<g>` 上，**绝不挂 `.pet-svg`** |
| **不能位移** | 身体跳起来时影子跟着飞，就没有重量感 | 阴影放在**不会动的容器**里；外层若要对宠物做位移动画，必须把阴影交给那个不动的最外层画（`hideShadow` + `.pet-shadow-scope`） |

**回归检查**：`PetLab` 页面（`/_petlab`）会一次性渲染 17 只各种形态/情绪的宠物，
是检验阴影的最快方式 —— 看一眼有没有哪只的影子歪了。

当前实现里，阴影**只在 `Pet.tsx` 一处绘制**，所以所有环节自动继承。
唯一的例外是 `PokePet`：因为它的跳动作用在父级容器上，会把 `Pet` 内部的阴影
一起平移，所以它用 `hideShadow` 把阴影提到自己那个不动的 `.pet-shadow-scope` 上画。

### 4. 按钮上的 `data-probe` 属性

`data-probe` / `data-variant` / `data-poison` / `data-mislabeled` 这些属性
是给自动化测试当锚点的，**看着没用，但删了测试就会用文字去猜按钮，非常脆**。
（改一个字就失效，我们为此浪费了很多时间。）

## 六、答辩口径（重要）

如果评委问"你们的 AI 是真的吗"：

> "我们的 AI 行为来自一张**预先训练好的模型能力表**。
> 真正的训练流程我们也跑通了（TensorFlow.js 在浏览器里训一个小型 CNN），
> 但为了保证**演示的节奏与可靠性**，产品里用的是离线结果。
>
> 这样做是有意的：如果现场训练，第一幕的'翻车'可能因为随机性而不发生，
> 整个教学剧本就崩了。教学演示需要**确定性**。"

**不要说"我们用了深度学习"** —— 那是虚的。说清楚"为什么不用实时训练"，
反而是加分项。

## 八、如果要加第 6 章

1. 在 `data/chapters.ts` 里加一条配置（含 `boss.digits`、`passRatio` 等）
2. 写 `chapters/Chapter6.tsx` —— 照抄 `Chapter2.tsx` 的结构，改参数
3. 写 `games/XxxGame.tsx` + `games/xxxRules.ts`（遵守第四节的约定）
4. 在 `ChapterPlay.tsx` 的渲染分支里加一行
5. 在 `store/petStore.ts` 的 `ChapterId` 类型里加上新 id

新章节只需要填「玩法」和「判定规则」两块。
